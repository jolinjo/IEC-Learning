# 1. 前言

## 1.1 本手冊的目的

IEC 81346-1 是工業系統、設施、設備與工業產品的「結構化原則與參考代號（Reference Designation）」基礎標準。簡單地說，它回答一個所有機電專案都會遇到的問題：圖面上的每一個元件、每一個功能、每一個安裝位置，應該怎麼命名，才能讓設計者、施工者、維護者與業主都指著同一個東西說同一句話。

本手冊的目標讀者有兩種：一是要「產出圖面」的機電設計工程師，說明如何依標準建立結構與編定代號；二是要「閱讀圖面」的現場人員、裝配技師、維護工程師與審圖者，說明如何拆解與解讀圖上的代號。手冊採用大量實務情境範例，讀者可以先讀第 2、4、7 章建立觀念，再依需要查閱其餘章節。

## 1.2 為什麼需要參考代號系統

一套機台或一座廠房動輒數百到數萬個元件。若命名各自為政（電氣圖叫 M1、機構圖叫「輸送馬達」、採購單叫「三相馬達 2HP」），跨部門溝通與後續維護的成本會非常高。參考代號系統的價值在於：

- **唯一性：**每個物件在專案內有唯一、可追溯的識別代號，圖面、BOM、I/O 清單、線號、銘板全部一致。

- **結構性：**代號本身就攜帶「屬於哪個系統、哪個功能群、裝在哪個盤」的階層資訊，看代號即可定位。

- **穩定性：**==功能、產品、位置三個面向分開編碼——設備換型號、移位置時，功能代號可以不變，文件不必大改。==

- **跨領域通用：**81346 不限電氣，機械、儀控、軟體、土建都可以用同一套結構原則，是機電整合（Mechatronics）文件的共同語言。

## 1.3 標準沿革與系列關係

IEC 81346-1 由 IEC 與 ISO 共同發行（故編號冠 8 開頭），前身是 IEC 61346-1，再往前可追溯到 DIN 40719 等各國規範。現行版本為 2022 年第 2 版，相較 2009 年第 1 版，主要新增了「型式面向（type aspect）」、參考代號系統的資訊模型、以及物件間關係的標示規則。

81346-1 只規定「基本規則」；實際編碼時還會搭配系列中的其他部與相關標準：

| **標準** | **內容** | **在設計流程中的角色** |
|---|---|---|
| IEC 81346-1:2022 | 結構化原則與參考代號基本規則 | 本手冊主題：面向、前綴符號、單層／多層代號 |
| IEC 81346-2:2019 | 物件分類與類別字母碼 | 決定 Q、K、B、M 等字母怎麼選（見第 5 章） |
| IEC 81346-12 | 營建工程與建築服務 | 建築機電（水電、空調）領域的應用部 |
| IEC 61355 | 文件分類與文件代號 | 圖紙、手冊等「文件」的編號 |
| IEC 60617 | 電氣簡圖用圖形符號 | 圖面上元件「長什麼樣子」 |
| IEC 61082-1 | 電氣技術文件的編製 | 圖面版面、跨頁參照的表示法 |
| IEC 60204-1 | 機械電氣設備安全 | 機台配線、標示的安全要求，引用 81346 作元件識別 |

**※ **81346-2 在 2009 與 2019 兩版之間類別定義有明顯調整（例如 2019 版取消了「多用途組合」的 A 類）。閱讀舊圖時請先確認該專案依據的版本，本手冊以 2019 版為準。

# 2. 核心觀念：物件與面向

## 2.1 物件（Object）

81346 把系統中任何值得被識別的東西都稱為「物件」：可以是一顆斷路器、一台馬達，也可以是「潤滑系統」這種抽象功能，甚至是一面盤體、一個房間。物件可以包含子物件，形成樹狀的部分／整體結構。參考代號做的事，就是替結構樹上的每個節點命名。

## 2.2 面向（Aspect）：同一個物件的三種（以上）視角

==這是整部標準最重要、也最常被誤解的觀念。==同一個物件，可以從不同角度去看：

- **功能面向（Function aspect）**——這個物件「做什麼」？不管它是什麼牌子、裝在哪裡。例如「主軸驅動功能」。

- **產品面向（Product aspect）**——這個物件「是什麼東西」？它是由哪些實體零組件構成的。例如「第 1 號變頻器」。

- **位置面向（Location aspect）**——這個物件「裝在哪裡」？例如「A1 電控盤內」「2 樓機房」。

- **型式面向（Type aspect，2022 版新增）**——這個物件「屬於哪一型」？用於同型設計重複出現的場合（型式／實例的區分）。

每個面向各自形成一棵結構樹，且以不同的前綴符號開頭：

| **前綴符號** | **面向** | **回答的問題** | **範例** | **典型用途** |
|---|---|---|---|---|
| **=** | 功能面向 | 它做什麼？ | =G1 | 功能群、系統、迴路的劃分 |
| **−** | 產品面向 | 它是什麼？ | -QA1 | 實體元件：斷路器、馬達、感測器 |
| **+** | 位置面向 | 它在哪裡？ | +A1 | 盤體、安裝板、房間、樓層 |
| **%** | 型式面向 | 它屬於哪一型？ | %P1 | 同型設計的型式定義（2022 新增） |
| **#** | 其他面向 | 專案自訂 | #… | 保留給特定應用領域自訂的面向 |

**※ **書寫時產品面向的前綴常以連字號「-」輸入（鍵盤上的減號）。部分舊系統或軟體（如 EPLAN 的舊制）另有 **==**（功能總成）與 **++**（安裝地點）等雙符號用法，那是承襲 IEC 61346 時代的慣例，不屬於 81346-1:2022 的基本規則；遇到時依該專案的圖例說明解讀即可。

## 2.3 為什麼要把三個面向分開？

因為功能、產品、位置三者的「變動週期」不同。以一台冷卻水泵為例：

- 它的**功能**「=G2 冷卻水供應」在整個廠房生命週期中幾乎不會變；

- 它的**產品**（某牌 5.5 kW 泵浦）十年內可能因故障換成別牌，產品序號會變；

- 它的**位置**可能因廠房改建從 +R1 泵房移到 +R2。

三面向分離後，換泵浦只需更新產品面向的資料，所有掛在「=G2 冷卻水供應」底下的 P&ID、操作手冊、警報清單一概不用改。這就是 81346 相對於「一顆元件一個流水號」的最大優勢。

## 2.4 同一元件的三面向組合表示

三個面向可以組合出現在同一個代號字串中，用來精確描述「哪個功能、由哪個產品實現、裝在哪裡」：

**=G1+A1-QA2**    「供電功能群 G1 之中、裝在 A1 盤內、編號 QA2 的開關物件」

組合時的閱讀順序沒有強制規定，但實務上多依「功能 → 位置 → 產品」排列。並非每張圖都要寫全三段——第 7 章會說明圖面上的省略規則。

# 3. 結構化原則

## 3.1 樹狀結構與單層代號

每個面向下，物件以「部分／整體」關係組成一棵樹。單層參考代號（single-level designation）用來識別某節點在其上一層物件中的身分，格式為：

**前綴符號 + 字母碼 + 序號**    例：-QA1、=G2、+A1

- 前綴符號：標明面向（=、-、+、%）。

- 字母碼：依 IEC 81346-2 的物件類別選取，一碼、兩碼或三碼大寫拉丁字母（不使用 I、O 以免與數字混淆）。

- 序號：阿拉伯數字，用來區分同層、同類別的多個物件。編號規則（是否補零、由何處起算）由專案規定，全案一致即可。

## 3.2 多層代號

多層參考代號（multi-level designation）把由樹根到目標節點沿途的單層代號串接起來，每一層都帶自己的前綴符號，形成一條唯一路徑：

**=G1=G2-MA1**    功能 G1 之下的子功能 G2 之下的馬達 MA1

**+A1+K2**    位置 A1（電氣室）之下的 K2（2 號盤）

**※ **不少 CAD／ERP 工具以「.」作層級分隔的簡寫（如 **=H10.H1**），意義等同逐層重複前綴。專案可以採用，但必須在圖例（legend）頁宣告，且全案一致。

## 3.3 頂節點（Top node）

結構樹的最上層節點代表整個系統或整座設施（例如整台機器、整個廠區）。2022 版明確引入頂節點的概念與標示規則，讓跨公司、跨專案交換資料時，能宣告「這串代號是從哪個頂點算起的」。實務上，單一機台專案常把機台本身當頂節點，其代號在圖框或專案設定中宣告一次，圖面內不再重複。

## 3.4 結構化的基本守則

- 一個物件在同一面向、同一層級內，代號必須唯一。

- 分層應反映真實的系統邏輯（功能樹照製程／機能分，位置樹照廠房／盤體分），不要為了編號方便硬造層級。

- 層數夠用就好。過深的樹（超過 4～5 層）會讓代號冗長難讀；過淺則喪失定位能力。

- ==同一專案內，分層邏輯、序號規則、省略規則必須成文（寫進專案設計準則），並在圖面圖例頁揭示。==

# 4. 參考代號的組成規則

## 4.1 語法總覽

一個完整參考代號字串，由一段或多段「面向區塊」組成，每段區塊又可以是多層：

**=G1=G3 +A1 -QA2 :4**    （為便於閱讀加了空格，實際書寫時連續不空格）

| **片段** | **名稱** | **意義** |
|---|---|---|
| =G1=G3 | 功能面向（兩層） | 功能群 G1 之下的子功能 G3 |
| +A1 | 位置面向 | 安裝於 A1 盤 |
| -QA2 | 產品面向 | 第 2 號開關物件（斷路器／接觸器） |
| :4 | 端子代號 | 該產品的第 4 號接點／端子 |

## 4.2 端子與接點：冒號「:」

元件的端子（terminal）以冒號接在產品代號之後，端子號依元件本身的印刷標示（製造商標示）書寫：

**-X1:5**    端子排 X1 的第 5 號端子

**-QA1:2/T1**    斷路器 QA1 的 2/T1 接點

**-KF2:A1**    繼電器 KF2 的線圈端 A1

## 4.3 書寫規則與禁止事項

- 字母一律大寫拉丁字母；類別碼不使用 I 與 O。

- 前綴符號是代號的一部分，圖面、BOM、銘板上都應完整書寫（含 -、=、+）。

- 同一物件的代號在所有文件（電氣圖、氣壓圖、程式註解、備品清單）中必須逐字一致。

- 不要把製造商型號、規格塞進參考代號（規格屬於元件屬性，寫在 BOM／元件表，不寫在代號裡）。

- 避免用代號隱含數量或規格語意（例如以 -QA10 表示 100A 開關）；序號只負責區分，不攜帶規格。

## 4.4 與舊命名習慣的對照

許多工程師熟悉的是 IEC 60204-1 附錄或 DIN 40719 時代的單字母慣例（K 繼電器、S 開關、F 熔絲…）。81346-2:2019 依「物件的固有功能」重新分類，部分字母的意義有變。閱讀新舊圖面時最容易踩到的差異：

| **元件** | **舊慣例（60204/DIN 時代）** | **81346-2:2019** | **說明** |
|---|---|---|---|
| 電力接觸器 | -KM1 | -QA1 | 切換動力電流屬「受控切換」Q 類 |
| 控制繼電器 | -KA1 | -KF1 | 處理訊號屬「資訊處理」K 類 |
| 斷路器 | -Q1 / -F1 | -QA1 | 主動作為「切換」歸 Q；純保護元件才歸 F |
| 熔絲 | -F1 | -FA1 | 保護物件 F 類 |
| 近接／極限開關 | -S1 / -SQ1 | -BG1 | 感測「位置／尺寸」屬 B 類 |
| 按鈕 | -S1 | -SF1 | 人機互動物件 S 類（手動轉訊號） |

**※ **公司若有大量舊圖資產，建議在設計準則中明訂「新專案採 81346-2:2019、舊圖維護沿用原代號」，並提供如上的對照表給現場人員，避免同廠房兩套語言造成誤解。

# 5. IEC 81346-2 類別字母碼

## 5.1 主類別（一碼）

81346-2:2019 依「物件的固有功能（inherent function）」定義了下列主類別。選碼時看定義、不看名稱直覺——問自己「這個物件本質上是在做什麼」：

| **碼** | **類別（意譯）** | **固有功能** | **典型例子** |
|---|---|---|---|
| **B** | 感測物件 | 把某物理量轉成可處理的訊號 | 感測器、變送器、CT/PT、極限開關 |
| **C** | 儲存物件 | 儲存能量、資訊或物料 | 電容、電池、儲槽、料倉 |
| **E** | 發散物件 | 發出輻射／熱／光 | 加熱器、照明燈具 |
| **F** | 保護物件 | 直接防護危險或非預期狀態 | 熔絲、突波保護器、安全閥 |
| **G** | 產生物件 | 產生能量流或物料流 | 發電機、電源供應器、泵浦、風機 |
| **H** | 物料處理物件 | 對物料進行加工處理 | 破碎機、反應器、加工單元 |
| **K** | 資訊處理物件 | 接收並處理訊號／資訊 | 繼電器（控制用）、PLC、控制器 |
| **M** | 驅動物件 | 產生機械驅動能量 | 電動機、致動器、汽缸（驅動） |
| **N** | 覆蓋物件 | 覆蓋、包覆 | 護罩、外殼、保溫層 |
| **P** | 呈現物件 | 把資訊呈現給人 | 儀表、指示燈、顯示器、蜂鳴器 |
| **Q** | 控制切換物件 | 受控地切換／調節能量、訊號或物料流 | 斷路器、接觸器、控制閥 |
| **R** | 限制物件 | 限制、穩定運動或流動 | 電阻、電抗器、節流閥、阻尼器 |
| **S** | 人機互動物件 | 把人的操作轉成訊號 | 按鈕、選擇開關、搖桿 |
| **T** | 轉換物件 | 轉換能量／訊號而不改變其種類 | 變壓器、變頻器、放大器、齒輪箱 |
| **U** | 保持物件 | 把物件保持在定位 | 支架、基座、絕緣礙子 |
| **W** | 導引物件 | 把能量／訊號／物料從一處導引到另一處 | 電纜、匯流排、管路、輸送滑槽 |
| **X** | 介接物件 | 提供連接介面 | 端子排、連接器、插座、法蘭 |

**※ **2019 版未使用 A、I、O，其餘字母（D、J、L、V、Y、Z）保留待用。舊版 2009 的 A 類（多用途組合裝置）已取消，但實務圖面仍常見以 -A1 標示成套裝置或組件（例如整組伺服驅動單元），屬沿用慣例，新設計建議依固有功能歸類。

## 5.2 常用子類別（兩碼）

主類別可加第二碼細分為子類別，第三碼再細分為次子類別。要用到幾碼由專案決定：小型機台常只用一碼即可；設備量大、種類多的專案建議統一用兩碼。以下為機電設計最常用的子類別節錄：

| **碼** | **子類別** | **典型元件** |
|---|---|---|
| **BA** | 電位感測 | 電壓感測、比壓器（PT） |
| **BC** | 電流感測 | 比流器（CT）、過載偵測 |
| **BF** | 流量感測 | 流量計、流量開關 |
| **BG** | 位置／尺寸感測 | 近接開關、光電開關、極限開關、編碼器 |
| **BL** | 液位感測 | 液位開關、液位傳送器 |
| **BP** | 壓力感測 | 壓力開關、壓力傳送器 |
| **BT** | 溫度感測 | 熱電偶、RTD、溫度傳送器 |
| **CA** | 電容性儲存 | 電容器 |
| **CC** | 電化學儲存 | 蓄電池、UPS 電池組 |
| **FA** | 過電流保護 | 熔絲 |
| **KF** | 電氣訊號處理 | 控制繼電器、PLC、安全繼電器 |
| **MA** | 電磁旋轉驅動 | 電動機 |
| **QA** | 電力迴路切換 | 斷路器、電力接觸器、電動機起動器 |
| **QB** | 隔離 | 隔離開關、負載開關 |
| **TA** | 電能轉換 | 變壓器、變頻器、整流器 |

**※ **完整子類別表請查閱 IEC 81346-2:2019 正文表格。選不到完全吻合的子類別時，退回使用一碼主類別是完全合規的做法；寧可用對一碼，不要用錯兩碼。

## 5.3 選碼決策順序

- 先問固有功能：這物件被設計來做什麼？（不是它裝在哪個迴路。）

- 在主類別表中找到唯一符合定義者。常見陷阱：凡「切換動力」都是 Q（含接觸器），凡「感測」都是 B（含極限開關），凡「處理訊號」都是 K（含控制繼電器）。

- 依專案準則決定是否加第二碼。

- 加序號。同層同類別由 1 起連續編（或依專案的區段編號規則）。

# 6. 設計工程師實務流程

## 6.1 建立結構的七個步驟

以下流程適用於新機台或新系統的電氣／機電設計，建議在畫第一張圖之前完成第 1～4 步：

- **步驟 1｜定義頂節點：**確定本專案結構樹的頂點（一台機器？一條產線？一座廠？），並決定專案代號與頂節點的宣告方式。

- **步驟 2｜建立功能結構（=）：**依製程或機能把系統分解成功能群（供電、驅動、安全、控制、潤滑…），必要時再分子功能。這一步與機械、製程工程師共同完成，是機電整合的介面。

- **步驟 3｜建立位置結構（+）：**依實體空間分解：廠房→電氣室→盤體→（必要時）盤內區段。

- **步驟 4｜制定編碼準則：**決定字母碼用幾碼、序號是否補零、多層分隔寫法、圖面省略規則，寫成專案設計準則文件。

- **步驟 5｜配置產品（-）：**設計各功能的實現方案，替每個實體元件編產品代號，並掛到功能樹與位置樹上（一個產品同時有三種身分）。

- **步驟 6｜貫穿所有文件：**電路圖、端子圖、BOM、I/O 清單、線號、銘板、程式變數註解，全部引用同一套代號。

- **步驟 7｜審查：**出圖前依 6.3 檢核表自我檢查，重點是唯一性與跨文件一致性。

## 6.2 命名決策的實務建議

- 功能結構「照系統邏輯」分，不要照盤體分——盤體是位置面向的事。最常見的錯誤是把功能樹畫成盤體清單。

- 序號預留擴充空間：同類元件可能增加時，序號跳號（10、20、30）或分段（1xx 給站 1、2xx 給站 2）都可以，但要寫進準則。

- 小專案可以只用產品面向（-）＋位置面向（+）；功能面向在系統夠複雜（多站、多迴路、多人協作）時效益才明顯。標準不強迫使用全部面向。

- 把「代號對照表（元件表）」當成交付物：每個代號一列，欄位含類別說明、規格、廠牌型號、所在圖號——讓看圖的人查得到。

## 6.3 出圖前檢核表

| **檢核項目** | **合格準則** |
|---|---|
| 唯一性 | 同一面向、同一層內無重複代號；全案無「同名不同物」 |
| 字母碼正確性 | 類別碼依 81346-2 定義選取，同類元件全案用同一碼 |
| 前綴完整 | 圖面、端子圖、BOM 上的代號都含前綴符號，未擅自省略 |
| 跨文件一致 | 電路圖、BOM、I/O 表、線號、銘板文字逐字相同 |
| 省略規則 | 圖框／圖例已宣告本頁隱含的高階代號（見 7.2） |
| 端子表示 | 端子一律用「:」接製造商標示，未自創端子號 |
| 準則文件 | 編碼準則已隨圖交付，新舊版差異已註記 |

# 7. 看圖指南：如何解讀參考代號

## 7.1 拆解四步驟

看到一長串代號，依前綴符號切段、由左往右讀，就能還原它的完整身分。以下用一個典型代號示範：

**=G1=G3+A1-QA2:4**

- 切段：**=G1=G3**｜**+A1**｜**-QA2**｜**:4**。

- 讀功能（=）：屬於功能群 G1（供電）之下的子功能 G3（例如 3 號饋線迴路）。

- 讀位置（+）：裝在 A1 盤。

- 讀產品與端子（- 與 :）：該功能由第 2 號開關物件（QA＝斷路器／接觸器類）實現，指的是它的第 4 號端子。

整句翻譯：「A1 盤內、供電功能群 G1 第 3 饋線迴路的 2 號斷路器，其第 4 端子」。

## 7.2 圖面上的省略規則（最重要的識圖知識）

圖面為了簡潔，通常不會把每個元件都寫全三面向。61082 系列允許以下做法，看圖時務必先確認：

- **圖框宣告：**本頁共同的高階代號寫在圖框（標題欄）或頁首，例如頁首標示 **=G1+A1**，頁內元件只標 **-QA2**。完整代號＝頁首＋元件標示。

- **就近繼承：**區域框（虛線框）上標示 **=G3**，框內元件繼承之。

- **相對代號：**代號未以前綴開頭寫全路徑時，表示相對於本頁宣告的節點。

**※ **拿到一套新圖，第一步永遠是找「圖例頁／符號說明頁」與圖框標題欄，確認：本案用了哪些面向、頁首隱含了哪些高階代號、多層分隔用什麼寫法。這三件事確認完，全套圖就讀得通。

## 7.3 跨頁參照

一個元件的不同部分常分散在不同頁（例如接觸器的主接點在動力迴路頁、線圈在控制迴路頁）。它們共用同一個產品代號，圖上並以「圖號／座標」互相參照：

**-QA2 → 12.3/B4**    線圈旁註記：主接點畫在第 12.3 頁座標 B4

==看圖時認代號不認頁面：只要代號相同，就是同一顆實體元件的不同部位。==

## 7.4 識圖速查表

| **看到…** | **意義** | **例** |
|---|---|---|
| = | 接下來是功能（系統／迴路） | =G1 |
| + | 接下來是位置（盤／房間） | +A1 |
| - | 接下來是實體元件 | -MA1 |
| : | 元件的端子／接點 | -X1:5 |
| 同符號重複出現 | 同一面向內的更深層級 | =G1=G3 |
| 代號中的「.」 | 層級分隔的專案簡寫（查圖例） | =G1.G3 |
| 相同產品代號出現在多頁 | 同一顆元件的不同部位 | -QA2 |
| 圖框上的代號 | 本頁所有元件隱含的高階代號 | =G1+A1 |

# 8. 實務情境範例

本章以五個由小到大的情境，示範代號如何規劃與解讀。所有範例皆採 81346-2:2019 兩碼子類別。

## 8.1 情境一：單站輸送機（入門）

一台皮帶輸送機：主電源進線、一台變頻驅動馬達、進出料各一顆光電感測器、一只現場操作盒。結構規劃：

| **面向** | **結構** | **說明** |
|---|---|---|
| 功能 = | **=G1** 供電功能 **=M1** 輸送驅動功能 **=K1** 控制功能 | 依機能分三群 |
| 位置 + | **+A1** 電控箱 **+B1** 機台現場 | 兩個安裝區 |
| 產品 - | 見下表 | 掛在功能樹下 |

| **完整代號** | **元件** | **解讀** |
|---|---|---|
| =G1+A1-QA1 | 主斷路器 | 供電功能、電控箱內、1 號切換物件 |
| =G1+A1-FA1 | 控制迴路熔絲 | 供電功能、電控箱內、1 號保護物件 |
| =M1+A1-TA1 | 變頻器 | 驅動功能、電控箱內、1 號電能轉換物件 |
| =M1+B1-MA1 | 輸送馬達 | 驅動功能、機台現場、1 號馬達 |
| =K1+A1-KF1 | PLC | 控制功能、電控箱內、1 號訊號處理物件 |
| =K1+B1-BG1 | 入料光電感測器 | 控制功能、機台現場、1 號位置感測物件 |
| =K1+B1-BG2 | 出料光電感測器 | 同上，2 號 |
| =K1+B1-SF1 | 啟動按鈕 | 控制功能、現場操作盒、1 號人機互動物件 |

**識圖練習：**維修單寫「**=K1+B1-BG2** 故障」。技師立即知道：去機台現場（+B1）、找出料端的光電感測器（BG2），而不必翻圖猜「B2 是哪顆」。

## 8.2 情境二：低壓配電盤（進線＋饋線）

一面 400 V 配電盤：1 路進線、1 組電容改善、4 路饋線。功能面向依迴路劃分，位置面向就是盤體本身：

| **完整代號** | **元件** |
|---|---|
| =G1+A1-QB1 | 進線隔離開關 |
| =G1+A1-QA1 | 進線斷路器（ACB） |
| =G1+A1-BC1 | 進線比流器（CT） |
| =G1+A1-BA1 | 比壓器（PT） |
| =G1+A1-P1 | 多功能電表（呈現物件，用一碼） |
| =G2+A1-CA1 | 功因改善電容組 |
| =G3+A1-QA1 ～ =G6+A1-QA1 | 第 1～4 路饋線斷路器（每路一個功能群 G3～G6） |

**設計要點：**注意四路饋線斷路器的產品序號都是 QA1——因為它們分屬不同功能群（=G3～=G6），在各自功能之下都是第 1 顆切換物件，不衝突。這正是功能結構的威力：迴路增減時，其他迴路的代號完全不動。

**識圖要點：**盤面銘牌若只寫 **-QA1**，必先對照盤內佈置圖或迴路銘板上的 **=G4** 等功能標示，確認是哪一路的 QA1。

## 8.3 情境三：雙泵互備泵站（功能與產品分離的威力）

冷卻水泵站：兩台泵互為備援，任一台都能滿足「供應冷卻水」的機能。規劃時把「泵送功能」與「泵浦本體」分開：

| **代號** | **物件** | **面向** |
|---|---|---|
| =G1 | 冷卻水供應功能（整體機能） | 功能 |
| =G1=G2 | 1 號泵送迴路 | 功能 |
| =G1=G3 | 2 號泵送迴路 | 功能 |
| =G1=G2+R1-MA1 | 1 號泵馬達（泵房 R1 內） | 功能＋位置＋產品 |
| =G1=G2+A1-QA1 | 1 號泵起動器（電控盤 A1 內） | 功能＋位置＋產品 |
| =G1+R1-BP1 | 共用出口壓力傳送器 | 功能＋位置＋產品 |

**威力展示：**三年後 1 號泵馬達燒毀，換成另一廠牌。產品資料（BOM 中 -MA1 那一列的型號、序號）更新，但代號 **=G1=G2+R1-MA1** 不變——P&ID、警報清單、SCADA 點位、維護紀錄全部不用改。若當初用「馬達流水號」命名，這次更換要改動的文件會多出數倍。

## 8.4 情境四：多站自動化產線（機電軟整合）

一條三站組裝線：上料站、鎖固站、檢測站。機械、電氣、軟體三個團隊共用同一棵功能樹：

**=H1**    產線頂層功能：產品組裝

**=H1=H10**    站 1：上料

**=H1=H20**    站 2：鎖固

**=H1=H30**    站 3：檢測

各站之下再掛驅動、感測、控制等子功能與產品。跨領域的效益：

- **機械：**站 2 的鎖固主軸標 **=H1=H20-MA1**，機構 BOM 與電氣圖指同一物。

- **電氣：**I/O 清單直接以代號命名——輸入點 I2.3 的說明欄寫 **=H1=H20-BG4**（鎖固到位感測）。

- **軟體：**PLC 變數命名 **H1_H20_BG4**，HMI 警報文字「=H1=H20-BG4 未到位」——操作員看到警報即可對照圖面與現場銘板。

- **維護：**備品倉把常用品掛在代號下（查 =H1=H20-MA1 即知規格與庫存）。

**序號跳號技巧：**站編號採 10、20、30，日後在站 1 與站 2 之間插入新站可用 =H15，不必重編全線。

## 8.5 情境五：讀一張陌生的圖（綜合識圖演練）

你拿到一張別人畫的控制迴路圖，圖框標題欄標示：

**=H1=H20 +A2**    （本頁功能：站 2 鎖固；本頁元件預設位置：A2 盤）

頁面中出現以下標示，逐一解讀：

| **圖上標示** | **完整代號（補上圖框宣告）** | **解讀** |
|---|---|---|
| -KF3:A1 | =H1=H20+A2-KF3:A1 | 站 2 的 3 號繼電器線圈 A1 端 |
| -SF2 | =H1=H20+A2-SF2 | 站 2 的 2 號按鈕（本頁預設在 A2 盤；若實裝於現場盒，圖上會另標 +B2 覆蓋預設） |
| +B2-BG4 | =H1=H20+B2-BG4 | 位置另標 +B2（現場），故為站 2 現場的 4 號位置感測器 |
| -QA2 → 15/C3 | =H1=H20+A2-QA2 | 接觸器 QA2 的其他接點畫在第 15 頁座標 C3 |
| =H1=H10-KF1 | =H1=H10+…-KF1 | 寫全功能路徑＝刻意跨出本頁範圍：引用站 1 的繼電器（跨站互鎖訊號） |

**心法：**元件標示比圖框「多寫」的部分（另標的 + 或寫全的 =）就是它與本頁預設不同之處——這是快速抓出跨區、跨站訊號的訣竅。

# 9. 常見問答（FAQ）

### Q1：一定要三個面向都用嗎？

不必。標準只要求「用到的面向依規則編」。小型機台常只用產品＋位置兩面向；功能面向在多站、多迴路、多人協作或業主要求資產管理時再導入。但同一專案內用法必須一致。

### Q2：接觸器到底是 K 還是 Q？

依 81346-2:2019，看固有功能：切換「動力電流」的電力接觸器是 QA（受控切換物件）；處理「控制訊號」的輔助繼電器是 KF（資訊處理物件）。舊慣例把兩者都叫 K（KM／KA），閱讀舊圖時需注意對照（見 4.4 節）。

### Q3：序號要不要補零（QA1 vs QA01）？

標準未規定。專案自訂即可，但全案一致，且 CAD、PLC、ERP 各系統要用同一寫法，避免 QA1 與 QA01 被當成兩個物件。

### Q4：可以用中文或自創字母當類別碼嗎？

不可以。類別碼限大寫拉丁字母且應依 81346-2 的類別定義；I、O 不使用。自訂需求（如廠區代碼）應放在頂節點或專案代號層級，不要混進類別碼。

### Q5：81346 的代號跟線號是同一件事嗎？

不是。參考代號識別「物件」；線號（導線識別）是配線層級的標示，另有其規則（IEC 60204-1 等）。但良好實務會讓線號可追溯到代號（例如以來源端子代號組成線號）。

### Q6：舊專案要不要全面改成 81346-2:2019 的碼？

通常不建議回頭改舊圖（風險高、效益低）。建議新專案採新版並訂出新舊對照表；舊機台大改造時再一併轉換。

### Q7：% 型式面向什麼時候會用到？

當同一型設計會被多次實例化時（例如標準機型出貨 50 台、或電廠中重複的機組），可用型式面向管理「型」與「實例」的關係。單件式專案一般用不到。

| 多層代號 | Multi-level designation | 由樹根到節點逐層串接的代號 |
| 頂節點 | Top node | 結構樹最上層節點（整個系統） |
| 類別碼 | Letter code (class code) | 依 81346-2 分類選取的字母 |
| 固有功能 | Inherent function | 物件被設計來做的事，選碼依據 |
| 端子代號 | Terminal designation | 以「:」接於產品代號後的接點標示 |
